# cc-data-lab

CC_Codex 二期（26.11）**数据工程**主线基线：**采集任务控制台**（Flask 后端 + HTMX 前端页 + 站内 Mock 目录）。

## 领域

- **所属领域**：数据工程  
- **子方向**：数据采集、爬虫与 RPA  

## 技术栈

- Python 3.12+、Flask 3、SQLite  
- HTMX（CDN）+ Jinja 模板  
- pytest  

## 本地运行

```powershell
cd claude-workspace\cc-data-lab
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pytest
python run.py
```

浏览器打开 http://127.0.0.1:5590 ，登录 **admin / 123456**。

流程：创建任务 → 选种子 `/mock/catalog/alpha` 或 `beta` → 详情页维护「必收 / 不收」两张清单 → 「运行采集」→ 查看落库（alpha 含重复标题，会演示去重跳过）。

### 必收 / 不收清单

任务详情页目录旁挂两张可编辑的单子：

- **左单「必收」**：本单编码本次目录里必须出现。开跑后若有编码在目录里缺席，页面顶部打出「缺必收」卡片并列出全部缺号；全部能见到则不出卡片。
- **右单「不收」**：本单编码开跑后全部进页面下方的「被挡清单」，不会落进账册（`crawl_records`）。
- 同一编码不能同时进两单；空编码两单都拒收。
- 任务一旦开跑（`running`/`done`），两张单子即锁定，增删改动一律挡下并提示。

## Docker 一键启动（推荐用于快照前验收）

需已打开 **Docker Desktop**：

```powershell
cd claude-workspace\cc-data-lab
docker compose up -d --build
docker compose ps
```

- 页面：http://127.0.0.1:5590/login  
- Mock：http://127.0.0.1:5590/mock/catalog/alpha  
- 停止：`docker compose down`（保留库卷）· 清卷：`docker compose down -v`

`docker compose ps` 中 `STATUS` 含 **healthy** 表示服务可访问。线下表「环境可复现等级」可填 **已容器化，可一键起环境**。
